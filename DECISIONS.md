# typethru — DECISIONS

Unattended-run decision log. Each entry: what was decided, and why, at the moment it was decided.

1. **Name: `typethru`.** Describes the mechanic (you type through the diff). Unclaimed on PyPI, npm, crates.io as of 2026-08-04. Rejected: `retype` (taken on PyPI by an unrelated annotation tool), `difftype`/`typediff` (read as "types of diffs"), `meatgate` (joke outlives the joke).
2. **Shape: TUI, not CLI-with-prompts.** Keystroke verification needs raw key events and live repaint; line-oriented input() cannot show per-character state. Diversification rule also satisfied: last three ships were non-interactive report CLIs.
3. **Stack: Python >= 3.10 + prompt_toolkit (pinned), git via subprocess.** Fit over novelty: prompt_toolkit is mature, handles Windows console + VT terminals, and — decisive — its `create_pipe_input` lets automated tests drive the real event loop end-to-end, which the verification gate needs on a headless run. Rust/Go TUIs were considered; discarded for verification-surface speed, not capability.
4. **Gate mode captures ALL tracked changes vs HEAD (staged + unstaged) as one session.** The target scenario is "the agent just ran on my tree". Splitting pre-existing human edits from agent edits is not knowable from git state; the contract is documented instead: run typethru when the pending diff is the thing you want to earn back.
5. **Untracked new files are excluded unless intent-to-add.** Reverting/restoring untracked content is the riskiest data path (no HEAD copy to fall back to). v0.1 lists them as "untracked, left alone" and documents `git add -N`. This keeps the destructive surface strictly to content git already has a copy of.
6. **Backup before revert, in `.git/typethru/`.** Post-state snapshot of every touched file plus a manifest, written and fsynced before any working-tree mutation. `restore` is a dumb copy-back — no diff math on the recovery path. Recovery must be boring.
7. **Indentation auto-fills by default.** Kamens/typing.io precedent: leading whitespace is navigation, not comprehension. Configurable off (`indent = "type"`).
8. **Deletions are shown, never typed.** You can't "type" an absence; requiring a confirmation keypress per deletion block is ceremony without comprehension value. Deletions ride along when their hunk is applied.
9. **No pedagogy claims.** The retyping-efficacy debate (HN 49153374) is unresolved; README frames typethru as ergonomics for a chosen practice, not a learning tool. This is also the honest defense against "why not just read the diff" — if that works for you, use hunk.
10. **Auto-apply globs default: `*.lock`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `Cargo.lock`, `uv.lock`, `poetry.lock`, `go.sum`, `*.min.*`, `dist/**`, `build/**`, `node_modules/**`.** Nobody's mental model improves by retyping a lockfile. Configurable.
11. **Practice mode included in v0.1.** Same renderer and typing engine with mutation turned off — near-zero marginal risk, directly serves the gittype issue's use case, and gives the verification gate a mutation-free path to exercise typing mechanics.
12. **ASCII-only UI output.** Carried lesson from wyoming-doctor (cp1252 Windows consoles). prompt_toolkit renders what we give it; we give it ASCII.
13. **Exit codes:** 0 = session completed (all hunks resolved), 1 = session ended with unapplied hunks (skips or early quit), 2 = usage/environment error. Mirrors diff-tool conventions from comfyui-diff.
14. **CRLF fidelity via byte-level file reconstruction.** Files are spliced as bytes with the original newline style preserved per line; typing compares the line's text content, newline handling never depends on what the user typed. D1/D8 verify.
15. **Non-UTF-8 files are auto-apply, not typeable.** A typing UI over undecodable bytes is nonsense; treating them like binaries (apply + report) keeps the byte-identity guarantee without lying about what was typed.
16. **Trailing whitespace is auto-filled like indentation.** It is invisible, so requiring it to be typed is a guessing game, not comprehension. Byte fidelity is unaffected (see 18).
17. **Configuration via `git config`, not TOML.** `git config typethru.indent type` / `git config --add typethru.autoapply "dist/**"`. Reasons: tomllib is 3.11+ while the floor is 3.10; a git-native tool gets local/global scoping, discoverability, and zero parsing code for free from git config.
18. **Diffs are computed, not parsed.** The session holds full base (HEAD) and target (captured) file contents and derives hunks with difflib; applying a hunk selects target lines for that region. Reconstruction always splices original bytes, so "all hunks applied == byte-identical to capture" holds by construction instead of by patch arithmetic. No unified-diff parsing anywhere.
19. **Renames handled as delete + add** (`git status --no-renames`). A rename with edits becomes a typeable new file plus an auto-applied deletion; rare enough that rename-tracking complexity is not worth its bugs in v0.1.
20. **Staged changes are unstaged for session files at capture time.** The index cannot be half-true while the worktree is being retyped; re-staging afterwards is one `git add`. Stated on the plan screen.
21. **Resume falls out of the backup model.** A session is "type from current tree state to the captured target". After a quit, rerunning `typethru` diffs the current tree (HEAD + typed hunks) against the retained backup target and continues with what remains.

## v0.2.0

22. **Compose sequences for unkeyboardable characters.** AI output is dense with em/en dashes, curly quotes, ellipses and non-breaking spaces; a typing gate that requires OS-specific incantations for them punishes the wrong thing. The expected character drives interpretation (`--` completes a dash only when a dash is expected), so ordinary hyphens are unaffected and no mode exists. Each compose keystroke counts in the stats: the effort was real.
23. **Live stats on by default (operator call).** Reverses v0.1's summary-only stance (principle 2, "progress is positional, not judgmental"). The operator wanted feedback; the principle survives in placement (screen edge), ink (chrome gray) and cadence (1s repaint, no animation). `typethru.livestats false` restores v0.1 behavior. Recorded as a revision, not a silent rewrite.
24. **Highlighting is earned, and only on the ANSI palette.** Completed lines get syntax color; the active line and ghosts stay gray, so color doubles as completion state and the sacred typing surface stays quiet. Pygments (second pinned dep) tokenizes the whole captured file once - correct for multi-line strings - and any line whose tokens fail to reproduce its exact text falls back to plain: a lexer must never change what's on screen.

## v0.3.0

25. **History lives beside the backup, never inside it.** The backup moved to `.git/typethru/backup/` so `drop` can't destroy `history.jsonl`; the pre-0.3 layout stays readable for anyone with an unfinished v0.2 session. History writes are best-effort - a logging failure must never break a session that just finished.
26. **Receipts are honest or nothing.** `Typed-thru: 6/9 hunks (2 auto, 1 untyped)` - the trailer states what was typed, auto-applied and waved through. Only complete, verified gate sessions can produce one. It's a claim you make in your own commit message; typethru just refuses to phrase it flatteringly.
27. **Delta pairing is positional and gated on similarity.** The k-th added line in a replace block pairs with the k-th deleted one; below a 0.5 SequenceMatcher ratio the pair is ignored and the full line is typed. Only the common prefix and suffix pre-fill - interior unchanged chunks are still typed, because mid-line cursor jumps would make the typing surface unpredictable.
28. **Pre-filled text may be typed through harmlessly.** The acceptance region runs to end-of-line even though the required region is smaller; muscle memory that keeps typing into a delta suffix (or trailing whitespace) is not an error. Errors begin past the end of the line.
29. **Repeat fill keys on stripped text and never re-seeds.** Same content at different indentation is still repetition; a repeat-filled line doesn't count as "typed" for seeding, so only text that actually passed through fingers unlocks auto-fill.
30. **Estimates are deliberately conservative.** Stripped-length chars at your median WPM (last 10 sessions, clamped 10-120 to survive robot-typist history), ignoring delta/repeat savings - real sessions come in under the estimate, never over.
31. **Multi-commit practice is oldest-first.** You read a codebase's history the way it was written. One session per commit keeps the header honest about where you are; the aggregate summary and the single history record treat the run as one sitting.
